(Index continues directly from the existing endpoint a(4). BOTH terms are certified by
**two genuinely different methods**, each independently implemented twice (four-way
agreement):

- **Method A (closed form, representation theory):** the Bruhat graph of S_n is the Cayley
  graph on all C(n,2) transpositions; since the transpositions form a full conjugacy class,
  the class sum acts as a scalar on every irreducible representation, so the Laplacian
  eigenvalues are indexed by integer partitions lambda of n: eigenvalue(lambda) =
  n(n-1)/2 - content_sum(lambda), with multiplicity f_lambda^2 (f_lambda = dimension of the
  irrep, via the hook-length formula). Excluding the trivial partition (n) (eigenvalue 0):
  a(n) = (1/n!) * Product_{lambda != (n)} eigenvalue(lambda)^(f_lambda^2)
  (Ehrenborg, 2021, "The number of spanning trees of the Bruhat graph", Adv. Appl. Math 125,
  102150 — this is exactly the closed form already used for a(1)..a(4) in the OEIS entry's own
  %F line).
- **Method B (explicit graph, direct Matrix-Tree):** build the actual n!-vertex graph (vertices
  = permutations, edges = pairs differing by any transposition) and compute the exact Laplacian
  cofactor determinant directly — no representation theory used at all.

Method A and Method B were each implemented independently by two separate lineages (this agent
and Codex/GPT-5, working from only the problem statement, no shared code) and all four
computations agree digit-for-digit on a(5) (120-vertex graph) and a(6) (720-vertex graph). a(7)
was also computed via Method A by both lineages (agreeing digit-for-digit, 6603 digits) but is
DELIBERATELY EXCLUDED from this submission: S_7 has 5040 vertices, too large for the Method-B
explicit-graph cross-check within budget, so a(7) has only single-METHOD (though dual-coder)
confirmation and is held back pending an independent-method check.)
